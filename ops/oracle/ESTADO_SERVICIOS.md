## Gate automático CI propuesto

Gate obligatorio antes de entregar un servicio: derivar de registry/ficha el puerto específico y `PORT`; comprobar parser de todas las variables obligatorias y condicionales, incluyendo reglas de `G6_CONNECTION_MODE` y flags; comparar `Dockerfile` ENV/EXPOSE/CMD/health, entrypoint, Compose env/env_file/mounts/ports/health y código; levantar imagen con dependencias aisladas para liveness + readiness + operación OpenAPI real; validar diffs HTTP contra OpenAPI y auth/routing; validar nombres Rabbit desde código contra AsyncAPI/topología y fallar si hay diferencia. Cuando las fuentes normativas discrepen, el gate debe bloquear solo el flujo afectado y requerir resolución del owner; no aceptar alias o “compatibilidad” inferidos. Esta es propuesta documental: no se modificó ni ejecutó workflow/CI como parte de este encargo.
